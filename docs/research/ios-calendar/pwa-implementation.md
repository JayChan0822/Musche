# PWA 日历实现记录（2026-10-14）

对应 [录屏与官方资料](README.md)、[MobileCal 静态逆向证据](native-findings.md)。这是 Web 上的交互重建，不包含 Apple 代码，也不声称复现私有弹簧求解器。

已实现：

- 手机月历紧凑日期和任务色条，点击色条进入当天。桌面卡片保留标题。
- 从月格到顶部周条的七个日期位置动画，返回时反向；源日期缺失时使用容器淡入淡出。今天用红色，其他选中日期用中性色。
- 前／当前／后三页共享纵向时间轴。横拖跟手、距离或速度判断提交、短拖回弹；竖向锁轴后不再横向导航。
- 周条切日和横滑翻日保留 scrollTop，首次打开保留原有任务／当前时间定位规则。
- 日视图触摸和滚轮不传给后台月历。第二指、touchcancel、关闭、动画中选择其他日期不会执行过期翻页。
- 普通区域允许原生滚动；时间轴 pan-y，事件块仍用原有编辑处理器。日期按钮提供选中与今天语义，减少动态效果时禁用转场动画。

Web 分页收尾使用 240 ms easing；这属于产品实现参数，不是对 iOS 日翻页参数的逆向结论。日期位置动画采用已发现的正常月／日转场时长 0.6 s，但没有复制 Apple 私有 spring。

仍有差距：本次未新增多日并排、月历捏合密度、月份窗口虚拟化，也未重写事件拖拽／拉伸。连续中断的速度衔接、真实 iPhone Safari／独立 PWA 的帧率和触觉仍需设备验证；桌面触屏仿真不等同于真机验证。模拟器 runtime 已安装，尚未确认 GUI 启动。

验证入口：`tests/mobile-day-view.test.mjs`（20 项），`tests/e2e/mobile-calendar.spec.mjs`（真实 Vue 组件、事件传播、scrollTop、预览页隔离）。

验证结果：语法检查、模块化检查、拆分状态回归、20 项日视图单元测试与生产构建通过。全量单元测试为 499 通过、1 跳过、1 失败：已有 `capacitor-removal.test.mjs` 要求删除 `ios/`，但仓库仍跟踪 SwiftUI 工程；未删除用户工程。桌面冒烟中月／周切换及新手引导通过，另外两项分别停在过时的 `1 Items` 文案、快速添加的 `Musician` 标签定位；本次未修改这些任务池／添加表单。手机浏览器专用用例已通过，验证事件传播、日期变化、时间位置、非活动页 inert 和月历实际 CSS 尺寸；不代表真实手指在 iOS 上的性能结论。

测试服务显式绑定 `127.0.0.1`，解决 macOS localhost 解析为 IPv6 与 Playwright 检查 IPv4 的不一致。
